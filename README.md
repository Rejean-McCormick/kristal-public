# kristal-public

**Public GitHub collection host for Kristal v10 states and approved derived reader surfaces.**

This is a hosted location and discovery surface, not a semantic authority. Repository visibility, reader synchronization, publication, release qualification and activation must remain separate decisions.

## Node and collection files

- `.kristal/node.json` — declared node identity and roles.
- `.kristal/bindings/github.json` — replaceable GitHub host locators and binding capabilities.
- `.kristal/capabilities.json` — declared capabilities.
- `state/state-snapshot.json` — the root/bootstrapped state, **not** the Zoology state.
- `kristals/zoology/state/state-snapshot.json` — the independently identified Zoology state.
- `.github/workflows/` — qualification and publication automation.

Do not assume a complete `kristals/index.json`, an approved AI read surface, a qualified Zoology release, or valid release/activation evidence exists unless the corresponding exact committed artifacts are present and independently verified.

## Publication safeguards

- Public synchronization is not an immutable publication, and a publication is not channel activation.
- Semantic identity and State Commitments do not change merely because GitHub URLs or paths change.
- A public branch/file is public data. Private or unapproved source content must not be committed or synchronized here.
- Initial public exposure requires explicit human approval of the correct state, collection, revision and scope; later revisions require the applicable independent qualification gate.
- A GitHub workflow's existence does not establish that independent approval, release controls or end-to-end qualification have passed.

See the [Kristal Framework](https://github.com/Rejean-McCormick/Kristal-Framework), [KristalDiag](https://github.com/Rejean-McCormick/KristalDiag) and [Konstellation Light](https://github.com/Rejean-McCormick/Konstellation-Light) for related contracts, diagnosis and read-only navigation.
